# 易道命理 — 完整部署方案

> 版本：0.1.0  
> 适用：本机开发、Windows 一键启动、Linux/云服务器生产部署  
> 关联：[部署检查清单](./部署检查清单.md) · [使用文档](./使用文档.md)

---

## 1. 访问地址一览

| 入口 | 本地默认地址 | 说明 |
|------|----------------|------|
| 用户前台 | http://localhost:9111 | 建档、测算、报告 |
| **管理后台登录** | **http://localhost:9111/admin/login** | 与前台账号分离 |
| 管理仪表盘 | http://localhost:9111/admin/dashboard | 登录后进入 |

### 默认管理员

| 字段 | 默认值 |
|------|--------|
| 用户名 | `admin` |
| 密码 | `admin123` |

生产环境务必修改 `.env.local` 中的 `ADMIN_PASSWORD`、`JWT_SECRET`，并在后台「系统设置」改密。  
说明：管理员密码在首次 `npm run db:seed` 时写入数据库；仅改环境变量不会自动覆盖已有库中的密码。

生产域名示例：

- 前台：`https://你的域名.com`
- 后台：`https://你的域名.com/admin/login`

## 2. Windows 双击一键启动

项目根目录已提供脚本（双击即可）：

| 文件 | 用途 |
|------|------|
| **`start.bat`** | 开发模式：自动装依赖 / 生成配置 / 初始化库 / 启动并打开浏览器 |
| **`start-prod.bat`** | 生产模式：`build` 后 `start`，适合本机或无 PM2 的服务器试跑 |

脚本会：

1. 检查 Node.js（需 18+）
2. 若无 `.env.local`，从 `.env.example` 复制
3. 若无 `node_modules`，执行 `npm install`
4. 若无 `data/suanming.db`，执行 `npm run db:seed`
5. 启动服务（默认端口 **9111**），并尝试打开前台与后台页面

停止服务：在黑色命令窗口按 `Ctrl+C`，或直接关闭窗口。

## 3. 环境要求

| 项目 | 要求 |
|------|------|
| Node.js | 18+（建议 20 LTS） |
| 包管理 | npm（随 Node 安装） |
| 磁盘 | 预留数据与构建目录写权限（`data/`、`.next/`） |
| 操作系统 | Windows / macOS / Linux |
| 反向代理（可选） | Nginx / Caddy，用于 HTTPS 与域名 |

本项目默认使用 **SQLite**（`better-sqlite3`），单机部署足够；无需单独安装数据库服务。

## 4. 配置文件

```bash
cp .env.example .env.local
# 用编辑器修改 .env.local
```

必改项（生产）：

| 变量 | 说明 |
|------|------|
| `JWT_SECRET` | 长随机串，勿用示例值 |
| `ADMIN_PASSWORD` | 首次 seed 前设置；已有库请在后台改密 |
| `NEXT_PUBLIC_SITE_URL` | 正式 HTTPS 域名，如 `https://example.com` |
| `NEXT_PUBLIC_SITE_NAME` | 站点名称 |

常用可选项：`VOLC_ARK_API_KEY`（AI）、`WECHAT_APP_ID` / `WECHAT_APP_SECRET`（公众号分享）、`AI_USER_QUOTA` 等。完整列表见 [使用文档 §9](./使用文档.md)。

## 5. 部署方式 A：本机 / 服务器直接跑 Node（推荐入门）

### 5.1 开发

```bash
npm install
cp .env.example .env.local
npm run db:seed
npm run dev
```

或 Windows 双击 **`start.bat`**。

### 5.2 生产

```bash
npm install
# 配置好 .env.local
npm run db:seed          # 首次
npm run build
npm run start            # 监听 9111
```

或 Windows 双击 **`start-prod.bat`**。

进程需保持运行；关机即停。长期运行请用下方 PM2 或 systemd。

## 6. 部署方式 B：PM2 守护（推荐生产）

适合 Linux 云主机长期在线。

```bash
# 安装 PM2（全局一次）
npm install -g pm2

cd /path/to/suanming
npm install
cp .env.example .env.local   # 并改好密钥与域名
npm run db:seed              # 首次
npm run build

# 启动（生产脚本）
pm2 start npm --name suanming -- start
pm2 save
pm2 startup                  # 按提示配置开机自启
```

常用命令：

```bash
pm2 status
pm2 logs suanming
pm2 restart suanming
pm2 stop suanming
```

更新代码后：

```bash
git pull
npm install
npm run build
pm2 restart suanming
```

> `db:seed` 在已有数据库上一般可重复执行以同步模块注册；上线前请先在测试环境验证，并做好数据库备份。

## 7. 部署方式 C：Nginx 反向代理 + HTTPS

Node 只监听本机 `127.0.0.1:9111`，由 Nginx 对外提供 443。

### 7.1 示例 Nginx 配置

```nginx
server {
    listen 80;
    server_name 你的域名.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name 你的域名.com;

    ssl_certificate     /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;

    client_max_body_size 20m;

    location / {
        proxy_pass http://127.0.0.1:9111;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

证书可用 Let’s Encrypt（`certbot`）签发。  
配置后将 `.env.local` 中 `NEXT_PUBLIC_SITE_URL` 设为 `https://你的域名.com`，然后重新 `build` + 重启进程。

### 7.2 安全建议

- 管理后台 `/admin` 可按 IP 限制（Nginx `allow` / `deny`）或仅内网访问
- 禁止搜索引擎抓取后台（`robots.txt` 或 Nginx 对 `/admin` 返回禁爬策略）
- 勿将 `.env.local`、`data/*.db` 提交到 Git 或公开目录

## 8. 部署方式 D：Docker（可选）

项目根目录提供 `Dockerfile` 与 `docker-compose.yml`：

```bash
# 1. 准备环境变量（必改密钥与域名）
cp .env.example .env.local

# 2. 构建并启动
docker compose up -d --build

# 3. 首次初始化数据库（数据落在宿主机 ./data）
docker compose exec suanming npm run db:seed
```

访问：http://localhost:9111 与 http://localhost:9111/admin/login

要点：

- `./data` 已挂载为卷，避免容器重建丢库
- 端口映射 `9111:9111`
- 镜像构建会编译 `better-sqlite3` 原生模块

无 Docker 环境时，直接使用方式 A/B 即可。

## 9. 数据与备份

| 路径 | 说明 |
|------|------|
| `data/suanming.db` | 默认 SQLite 主库（用户、档案、报告、配置等） |
| `.env.local` | 密钥与站点配置（勿提交） |
| `.next/` | 构建产物，可不备份，可重新 `build` |

建议每日备份数据库：

```bash
# Linux 示例：复制一份带日期的备份
cp data/suanming.db "backup/suanming-$(date +%Y%m%d).db"
```

Windows 可用任务计划程序复制 `data\suanming.db` 到备份目录。

恢复：停止服务 → 用备份覆盖 `data/suanming.db` → 再启动。

## 10. 上线流程（推荐顺序）

1. 准备服务器：Node 18+、防火墙放行 80/443（或仅内网 9111）
2. 拉取代码，配置 `.env.local`
3. `npm install` → `npm run db:seed` → `npm run build`
4. 用 PM2 启动 `npm start`
5. 配置 Nginx + HTTPS，改 `NEXT_PUBLIC_SITE_URL` 后重新 build/restart
6. 浏览器访问前台与 **`/admin/login`**，改管理员密码
7. 按 [部署检查清单](./部署检查清单.md) 逐项冒烟
8. （可选）配置 AI、微信、小程序、Android 壳（见对应文档）

## 12. 常见问题

**Q：打不开管理后台？**  
确认地址是 `/admin/login`（不是 `/login`）。服务需已启动，端口默认 9111。

**Q：admin / admin123 登不上？**  
执行过 seed 且之后在后台改过密码，则环境变量里的默认密码无效。可用已改密码登录；或在备份后重置库并重新 seed（会清空业务数据，慎用）。

**Q：改了 `.env.local` 不生效？**  
开发模式需重启 `npm run dev`；生产模式改公开变量后通常需重新 `build` 再 `start`。

**Q：端口被占用？**  
修改 `package.json` 中 `dev` / `start` 的 `-p 9111`，或释放占用进程；反向代理时改 `proxy_pass` 端口保持一致。

**Q：`better-sqlite3` 安装失败？**  
Windows 需可用的构建环境；Linux 安装 `build-essential` 等后再 `npm install`。
